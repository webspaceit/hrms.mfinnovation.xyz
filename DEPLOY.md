# Deployment Guide — Shared Hosting (no Node, no Composer)

This system is **pure PHP 8 + MySQL** — there is no build step, no package
manager, and no framework to install. Upload the files, import the SQL,
fill in one config file, and it runs.

---

## 1. Prerequisites

| Requirement | Notes |
|---|---|
| PHP 8.0+ | Any shared hosting in the last few years qualifies |
| MySQL 5.7+ / MariaDB 10+ | Standard cPanel/Plesk hosting |
| Apache with `mod_rewrite` | Default on most shared hosts — pretty URLs need it |
| Writable folders | `logs/`, `uploads/signatures/`, `uploads/tenants/` |

The installer (`install.php`), all `ajax/*.php` endpoints and all cron
scripts are plain files — nothing to compile or bundle.

---

## 2. Build the package (on your dev machine)

```
php tools/build_deploy.php
```

This writes `oop-rms-deploy.zip` next to the project. Pass
`--base-url=/rms/` if you are installing in a sub-folder, and
`--db-user=…  --db-pass=…  --db-name=…` to have the database values filled
in for you. The script also prints a short report of what it excluded and
scans the result for development leftovers.

Add `--no-zip` to stop at the staging folder (`_deploy-stage/rms`) if you
would rather inspect the files before zipping.

**Not included in the package** — all deliberate:

| Excluded | Why |
|---|---|
| `.git/` `.kilo/` `.gitignore` | version control metadata |
| `config/config.php` | replaced by a generated production config |
| `logs/*` | your development error log |
| `uploads/*` (files) | tenants' NIDs, deeds, signatures — your live data, not code |
| `tools/` | the build script itself |
| `uploads.zip`, `*_upgrade.sql` (other than `db_alter_upgrade.sql`) | superseded archives / one-off scripts |

---

## 3. Upload the files

1. Unzip `oop-rms-deploy.zip`. It contains a single `rms/` folder.
2. Upload **everything inside it**, keeping the folder structure, into your
   web root (`public_html/`, `httpdocs/`, …) — either directly at the root
   or inside a sub-folder.
3. The `.htaccess` files **must be uploaded** — some FTP clients hide
   dotfiles. Check that these arrived:
   - `rms/.htaccess` (routing + hardening)
   - `rms/config/.htaccess` (blocks the folder holding your DB password)
   - `rms/logs/.htaccess`
   - `rms/uploads/tenants/.htaccess`, `rms/uploads/signatures/.htaccess`
     (these block PHP execution inside the upload folders)

---

## 4. Create the database

Create an empty database in your host's MySQL panel first (on cPanel the
name is usually prefixed with your account, e.g. `myuser_rmsdb`).

Then pick one:

**Option A — phpMyAdmin (recommended):**

1. Open phpMyAdmin → select the database you just created.
2. **Import** → choose `database.sql`.
3. All 11 tables are created, with the default settings rows seeded.
   No demo data and **no default admin account** are inserted.

> `database.sql` deliberately does **not** contain `CREATE DATABASE` or
> `USE` — those are commented out, because on shared hosting a hardcoded
> `USE oop_rms` would silently point the import at the wrong database.

**Option B — built-in installer:**

1. Open `https://yourdomain.com/install.php` (or `/rms/install.php`).
2. Click **Install Database**, then **Create Admin User**.

The installer also notices when the tables are already there (e.g. after a
phpMyAdmin import) and skips straight to the admin step.

> **Security:** once setup is finished, **delete `install.php`** from the
> server. It has no built-in auth — anyone who finds it can re-run it.
> Until you delete it, it shows *Installer Locked* rather than re-running
> by itself, but do not rely on that.

## 5. Configure the app

The package already contains a production `config/config.php` (generated by
the build script, safe defaults, errors logged not displayed). Edit it and
fill in **three values**:

```php
define('DB_USER', 'YOUR_DB_USER');
define('DB_PASS', 'YOUR_DB_PASSWORD');
define('DB_NAME', 'YOUR_DB_NAME');
```

- **DB_HOST** is usually `localhost` on shared hosting — leave it.
- **BASE_URL** — the trickiest one; every link is built from it:
  - `'/'` for `example.com/` ← the default, and the built-in package's value
  - `'/rms/'` for `example.com/rms/`
  - Keep the **leading and trailing slash** — a missing `/` breaks all URLs.

That is all `config/config.php` holds. Everything else the app needs
(`DB_PREFIX`, `SITE_NAME`, `CURRENCY`, `DEFAULT_LANG`, `CSRF_*`,
`MAX_UPLOAD_SIZE`, `MAX_IMAGE_DIM`, `GS_PATH`, `NOTE_FONT_CHOICES`) is defined
as guarded defaults near the top of `classes/init.php` — a file that already
existed, so it is always replaced on upload.

> **On updates: keep your `config/config.php`, replace everything else.**
> An old `config.php` is always safe: every constant it does not define falls
> back to the guarded defaults in `classes/init.php`, and anything it does
> define wins. This is deliberate — an outdated `config.php` can never take the
> site down, and a missing new file can never take it down either.

To change a default permanently, set it in `config/config.php` (which always
wins), or edit the defaults block in `classes/init.php`.

`config.production.example.php` ships alongside it as the untouched
template. Do not put the real password in that file.

## 6. Folder permissions

Your hosting must let PHP write to:

- `logs/` — error log file is created here
- `uploads/signatures/` — owner signature image
- `uploads/tenants/` — tenant documents (NID / deed)

Typical shared hosting: `755` for directories and `644` for files already
works; if uploads fail, try `775` on those three directories.

## 7. Clean URLs & the router

### How it works
- `index.php` is the **single front controller** — every page is a route:
  `payments`, `flats`, `tenant-payments`, …
- `app/routes.php` maps each route to a Controller method; Controllers
  render Views; Models/classes handle data.
- The rewrite hands anything that is not a real file/folder to the router:
  `example.com/payments` → `index.php?r=payments`.

### Apache (shipped — `.htaccess`)
The root `.htaccess` contains the rewrite plus hardening rules that deny
`*.sql`, `*.log` and dotfiles anywhere in the tree, and switch off
directory listings. The rewrite part is:

```apache
Options -MultiViews

RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^([a-zA-Z0-9_/-]+)/?$ index.php?r=$1 [L,QSA]
```

Two things to know:

1. **`Options -MultiViews` is REQUIRED.** Apache's content-negotiation can
   silently map `/payments` to a file named `payments.php` and bypass the
   router entirely.
2. If your host reports *"RewriteEngine not allowed"* or *"...not allowed
   here"*, they have `AllowOverride None` — ask support to enable
   `AllowOverride All` for your folder, or use the `<VirtualHost>` snippet
   below. The app still works without the rewrite; you just get
   `index.php?r=payments` URLs.

If you control the Apache config (VPS/dedicated):

```apache
<Directory /var/www/html/rms>
    Options -MultiViews
    AllowOverride All
</Directory>
```

### nginx (if your host uses it)
Most nginx hosts run PHP-FPM through a proxy. Put this inside the
`server { }` block and reload nginx:

```nginx
location / {
    try_files $uri $uri/ /index.php?r=$uri;
}
```

### No rewrite at all (fallback)
The app **works without** rewriting too — URLs just become
`index.php?r=payments`. Every page still functions via that form.

## 8. Scheduled task (auto invoice generation)

`cron/invoices.php` generates + auto-sends monthly invoices. Guard it with
the token you set in the invoice settings, and run it daily:

```cron
# cPanel cron — every day at 09:00 (auto-send only triggers on the
# first days of the month, before the configured deadline day)
0 9 * * * php /home/USER/public_html/rms/cron/invoices.php YOUR_TOKEN >> /home/USER/public_html/rms/logs/cron.log 2>&1
```

No CLI? Use the HTTP form (still token-guarded) — cPanel cron or an
external service like cron-job.org:

```
https://example.com/rms/cron/invoices.php?token=YOUR_TOKEN
```

Dry run (prints the plan without sending):

```
php cron/invoices.php YOUR_TOKEN --dry
```

`cron/` is intentionally reachable over HTTP, so this fallback keeps
working.

## 8b. Due-date reminder cron (optional)

Reminders reuse the same gateways as invoices. They need their own daily run:

`
# cPanel cron - every day at 10:00 (or Windows Task Scheduler on a local box)
0 10 * * *  /usr/local/bin/php /home/USER/public_html/oop_rms/cron/reminders.php TOKEN
`

The token comes from **Settings -> Rent Reminders -> Reminder cron token**.
Hosts without CLI can call https://yourdomain/cron/reminders.php?token=TOKEN.

Useful flags:

`ash
php cron/reminders.php TOKEN --dry            # print the plan, send nothing
php cron/reminders.php TOKEN --today=2026-12-01
php cron/reminders.php TOKEN --push-test      # test notification to every device
`

Browser push needs **HTTPS**. Generate the VAPID keys once in
**Settings -> Rent Reminders -> Generate keys** and do not change them after
tenants have subscribed (their subscriptions are tied to that key).
## 9. PDF compression (optional)

Uploaded PDFs are re-compressed with Ghostscript when:

- PHP `exec()` is allowed, **and**
- Ghostscript is installed, **and**
- `GS_PATH` in config points to the binary.

On hosts that block `exec()` (common on cheap shared hosting), leave
`GS_PATH = ''` — documents upload uncompressed, nothing breaks.

## 10. Upgrade an existing install

If you already had an older version, **do not** import `database.sql` —
it would create empty tables. Instead:

1. **Back up first.** In phpMyAdmin: select the database → Export → SQL.

2. **Rename tables to the prefixed schema**, if your old database still has
   unprefixed names (`users`, `flats`, …):

   ```sql
   RENAME TABLE users TO wsit_users, buildings TO wsit_buildings,
     flats TO wsit_flats, tenants TO wsit_tenants, leases TO wsit_leases,
     payments TO wsit_payments, expenses TO wsit_expenses,
     settings TO wsit_settings, translation_cache TO wsit_translation_cache,
     invoices TO wsit_invoices, invoice_sends TO wsit_invoice_sends;
   ```

4. **Run `db_reminders_upgrade.sql` once** if you want due-date reminders (creates `wsit_push_subscriptions` + `wsit_invoice_reminders`).

3. **Run `db_alter_upgrade.sql` once** (phpMyAdmin → Import). It is the
   single *ALTER-only* upgrade that adds every column and table a newer
   build needs: shop names, holding numbers, service-charge uploads and
   their month/year, receipt note colour and font, parking/gas/water/waste
   amounts, arrears, invoice status tracking, user roles, tenant-portal
   columns, and the `receipt_type` values `water`/`waste`.

   It never drops or overwrites data and is fully idempotent, so it is safe
   on a database that is already current. All existing user accounts are
   kept as `admin` — reassign individual ones from the **Users** page.

5. Replace the files with this package, keeping your existing
   `config/config.php`, `uploads/` and `logs/`.

6. The old page URLs (`payments.php`, `flats.php`, …) are gone — bookmark
   the new clean ones (`/payments`, `/flats`, …). Old links 404 by design.

## 11. Go-live checklist

- [ ] Database created and `database.sql` imported
- [ ] `config/config.php` filled in (BASE_URL exact, leading + trailing `/`)
- [ ] Admin user created via `install.php`
- [ ] `install.php` **deleted** from the server
- [ ] `logs/`, `uploads/signatures/`, `uploads/tenants/` writable
- [ ] All five `.htaccess` files present
- [ ] `/payments` and `/flats` open as clean URLs
- [ ] `https://yourdomain.com/config/config.php` returns **403**, not your
      password (if it does not, your host ignores `.htaccess` — delete that
      file's password from public view by adding a deny rule in
      `public_html/.htaccess`)
- [ ] `cron/invoices.php` scheduled with its token
- [ ] Test: bilingual switch works, receipt/invoice print fine
- [ ] Non-Apache hosts: rewrite block applied (or accept `index.php?r=` URLs)
